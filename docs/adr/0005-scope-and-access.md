# ADR-0005: 服务范围与访问者边界

- 状态：已接受
- 日期：2026-11-16

## 背景

需要明确"暴露什么"和"谁能访问"，这两条决定认证、加密、限速的复杂度。

## 决策

- 一期支持两类代理：`http`（Web 站点）和 `tcp`（数据库/自定义 TCP）。不做 UDP。
- 访问者范围限定为"自己 + 少数可信的人"，不做匿名公开访问。

## 理由

- HTTP/Web 是最常用场景；数据库/TCP 是明确提出的第二个需求。
- UDP 可通过 frp 实现但配置与测试另走一套，一期不引入以免分散。
- "少数可信的人"意味着接入认证（token/密钥）+ 传输加密（TLS）足够，不需要计费、多租户、细粒度 RBAC 那套。

## 后果

- 数据库端口暴露到公网是高风险面，需要在 TCP 入口做访问控制（来源 IP 白名单或强 token），不能裸奔（见待决项）。
- 若将来要公开给陌生人，需要重新评估：WAF、限流、防滥用、审计日志都要补上，是一粒新的 ADR。
- UDP 需求出现时再开新 ADR，不塞进本决策。
