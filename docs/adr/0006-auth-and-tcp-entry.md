# ADR-0006: 接入认证与 TCP 入口握手

- 状态：已接受
- 日期：2026-11-16

## 背景

访问者范围是"自己 + 少数可信的人"，但要暴露两类服务：HTTP（经 Caddy）和数据库 TCP（frps 直监听）。TCP 端口裸在公网会被扫描，需要认证门槛。

## 决策

- **frpc 接入**：每个 frpc 客户端一个 token，连接时出示，frps 比对；传输强制走 `wss`（TLS）。
- **TCP 入口**：访问者连上 frps 的 TCP 监听端口后，先发 token 握手，通过才建立到 frpc 的数据流；未通过直接断开。

## 理由

- 威胁模型是"防意外暴露"而非"防定向攻击"，token + TLS 足够，不上非对称签名。
- 数据库 TCP 不能裸绑公网，一层 token 握手成本很低但堵住扫描器。
- "每客户端一 token"而不是"每服务一 token"，避免管理一堆 token。

## 后果

- token 泄露 = 该客户端全部代理失守，需要能吊销/轮换 token（见管理面分支，待定）。
- TCP 入口的 token 握手是自定义协议，非原生数据库客户端无法直接连——用户可能需要一个本地小代理或用支持自定义连接串的客户端（这个限制要写进 README）。
- wss 意味着 Caddy 要能代理 WebSocket 升级，且证书有效。
