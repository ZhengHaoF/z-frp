# ADR-0011: dashboard 从只读升级为隧道管理面

- 状态：已接受
- 日期：2026-11-16
- 取代：[0009](0009-dashboard-and-ops.md) 的"dashboard 只读"、[0010](0010-key-based-tunnel-provisioning.md) 第 2 节"新建入口仅 CLI、dashboard 保持只读"及其后果段"完整可写管理面仍需另开 ADR"

## 背景

二期（ADR-0010）实现后，dashboard 能展示隧道清单，但页面明确写着"新建/轮换请在服务端用 CLI"。用户看到同类产品（如截图中的隧道管理弹窗）后提出：能否在网页上直接新建隧道，不必每次登录服务器敲命令。

评估后确认：这是可行且值得的改进。隧道创建/轮换/删除的底层逻辑已在 `packages/frps/src/tunnels.ts` 中实现（`cmdCreate` / `cmdRotate` / `cmdDelete`），存储层已是原子写，basic auth 也已存在。主要工作是新增写接口与表单页，不需要重写隧道模型。

但同类产品的界面不能直接照抄，存在四处硬差异（见"裁剪"一节）。

## 决策

### 1. 写入范围：建 + 轮换 + 删除全部放到网页

- 隧道清单每行提供"轮换"与"删除"操作，配一个"新建隧道"入口。
- CLI 的四个子命令（`create` / `list` / `rotate` / `delete`）保留，网页与 CLI 是同一份 `tunnels.json` 的两个前端，互不取代。
- 理由：key 会泄露、隧道会废弃，建/轮换/删除是日常操作，网页上闭环最省事，不必再回服务器。

### 2. 权限：沿用现有 basic auth 单账号

- 不引入第二个管理密码、不做读写分账号、不做二次确认。
- **必须接受的取舍：能看 dashboard = 能建/删隧道/轮换 key。**
- 配套要求（写进 README）：dashboard 只绑内网回环，或经 SSH 隧道 / Caddy + basic auth 访问，禁止公网裸奔。这一条从"建议"升级为"安全前提"。
- 不做 CSRF token：basic auth 下风险有限，且当前是单机可信人群场景。

### 3. 隧道类型：只暴露实际支持的 TCP 与 HTTP

截图中的五类能力按如下裁剪：

| 截图能力 | 处理 | 原因 |
|---------|------|------|
| TCP 隧道 | 保留 | 已实现 |
| HTTP 建站隧道 | 保留 | 已实现 |
| UDP 隧道 | 不提供 | ADR-0005 明确不做 |
| HTTPS 建站隧道 | 不做为独立类型 | 本架构 HTTPS 由前置 Caddy 统一终止，所有 HTTP 隧道天然支持 |
| WOL 开机隧道 | 不提供 | 无对应实现 |
| 顶部节点选择 | 不提供 | 单机单节点，无多节点概念 |
| 远程端口留空自动生成 | 不提供，保留手填 | 端口池分配是二期 ADR 否决过的选项，不在本次范围 |
| 自动 HTTPS 开关 | 不提供 | Caddy 已统一处理，开关无意义；动态改 Caddyfile 是另一块复杂度 |

界面上用一行灰字注明"UDP / HTTPS / WOL：当前版本不支持"，避免用户误以为功能缺失。

### 4. HTTP 表单：切换类型时动态换字段

- 选 TCP：远程端口 + 本地 IP + 本地端口 + 访问密码（authToken，带生成按钮）。
- 选 HTTP：完整域名（如 `a.b.com`）+ 本地 URL；不显示 authToken（HTTP 隧道没有 AUTH 握手入口）。域名模型见 ADR-0012。
- 用少量前端 JS 根据 select 值切换字段组的显示，不引入前端框架。

### 5. key 显示：创建成功时显示一次，带复制按钮

- 创建接口在响应中回传完整 key（与 CLI "只显示一次"的语义一致），页面展示供复制。
- 隧道清单仍只显示 key 前缀。不在清单提供"随时查看完整 key"，避免 basic auth 账号泄露 = 全部 key 泄露。

## 实现要点（不影响架构）

- `cmdCreate` 目前把校验错误直接 `process.stderr.write` 并 `return 1`，不适合 HTTP 复用。需要从 `tunnels.ts` 抽出一个纯函数（入参为表单字段，返回 `{ ok: true, record }` 或 `{ ok: false, error }`），CLI 与网页接口共用，避免校验逻辑复制两份导致行为漂移。
- 新增字段 `note`（备注）到 `TunnelRecord`，需同步 `shared` 类型、`tunnels.json` 结构与 dashboard 展示；旧记录缺该字段时按空字符串兼容。
- dashboard 现在用 meta refresh 每 10 秒整体刷新，加表单后要改成局部刷新或手动刷新，否则填表到一半会被刷掉。
- 网页写入与 CLI 写入都可能碰 `tunnels.json`，沿用现有原子写；两者并发概率极低，可信人群规模下可接受，不引入 SQLite。

## 理由

- 底层逻辑已存在，新增的只是 HTTP 接口与表单，改动集中在 `dashboard.ts` 与 `tunnels.ts`，风险低。
- 网页 + CLI 共用同一份存储与校验逻辑，避免两套真相源。
- 裁剪掉不支持的类型，避免做出"能选但选了没用"的假功能。
- 沿用 basic auth 不再加一层账号体系，符合"少数可信的人"的威胁模型，但必须用文档把"dashboard 不可裸奔"钉死。

## 后果

- 推翻 ADR-0009 与 ADR-0010 的"dashboard 只读"结论；dashboard 从状态页升级为管理面，代码量与攻击面都增加。
- basic auth 账号的权限从"只读"升级为"完全控制"，共享账号前需三思。
- 需要一条新 ADR 覆盖本决策（即本文）；DESIGN.md 决策清单新增第 11 条。
- 隧道清单的操作按钮要防误触（至少一次前端确认），删除操作不可撤销。
- 完整多租户 / RBAC / 审计日志仍不在范围内。
