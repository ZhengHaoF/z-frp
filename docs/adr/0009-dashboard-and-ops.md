# ADR-0009: 只读 dashboard 与运维约定

- 状态：已接受
- 日期：2026-11-16

## 背景

一期需要可观测能力，且用户明确问过"是不是得做个网页端来管理"。必须把"看状态"和"改配置"拆开，否则会出现一个既不能改配置又权限混乱的四不像。

## 决策

- **dashboard 只读**：展示在线客户端、代理状态、连接数、流量。不提供增删改代理、token 管理、配置热更新。
- **暴露方式**：独立子域名（如 `dash.frp.example.com`）经 Caddy，加 HTTP basic auth 密码保护。
- **配置真相源**：`frpc.json` / `frps.json` 文件。改配置 = 改文件 + 重启。
- **配置文件格式**：JSON，与控制帧一致，解析器零额外依赖。
- **TCP 端口分配**：frpc 配置里手填 `remotePort`（如 33061），frps 校验不与已占用端口冲突。
- **客户端数量**：一个 frps 接多个 frpc，各自独立 token；streamId 需带客户端维度避免碰撞。
- **心跳**：30s 心跳 / 90s 无响应判死。
- **一期运维**：结构化日志 + systemd 服务文件。不做 Prometheus 指标导出。

## 理由

- 只读 dashboard 不需要存储状态、不需要写权限模型，几百行就能闭环；完整管理面相当于在 frp 里嵌一个 CMS，是一整块独立设计，不该悄悄塞进一期。
- 基本认证挡住随手访问足够；"少数可信的人"不需要 SSO。
- JSON 手填端口直观可控，也能被未来的网页端直接复用为字段。
- 多客户端 + 独立 token 符合"你和几个可信的人各跑各的"的真实用法。
- 30s/90s 是公网长连接的常规值，兼顾灵敏与误判。

## 后果

- 改配置要重启，期间隧道会断——可接受，但要在 README 里写清楚。
- dashboard 泄露服务清单与流量信息，密码要够强且不能与其他系统复用。
- 多个 frpc 时，任一客户端的重连风暴都要做幂等，否则路由表会被污染。
- 若将来要做可写管理面，需要另开 ADR 回答"配置存哪、谁能改、怎么热生效、token 怎么吊销"，不能直接在本版 dashboard 上加按钮。
