# ADR-0001: 自研 frp，而非采用现成方案

- 状态：已接受
- 日期：2026-11-16

## 背景

需求是把本地服务通过有公网 IP 的服务器暴露到公网，供他人访问。候选方案有三类：

1. 托管隧道服务（Cloudflare Tunnel、ngrok 等）
2. 部署现成开源 frp（官方 frps/frpc）
3. 自己写代码做一套 frp

## 决策

选第 3 条：自研 frpc + frps。

## 理由

- Cloudflare Tunnel 免费、无需公网 IP、无需备案域名，但在中国大陆网络环境下连接不稳定，访问者经常连不上——这是否决它的决定性因素。
- 部署官方 frp 可行，但工作区专门命名为 `z-frp`、从零起项，目标是"自己写代码做"，而非"配一套现成服务"。
- 自研换取对协议、认证、路由的完全控制，且技术栈可统一到团队熟悉的 Node.js（见 ADR-0002）。

## 后果

- 需要自己实现认证、多路复用、断线重连、流量控制等官方 frp 已解决的问题。
- 安全责任全部落在自己身上，任何认证/暴露面的疏漏都由自己承担。
- 长期维护成本高于部署现成方案，这是为"可控性 + 学习/产品化"付出的明确代价。
